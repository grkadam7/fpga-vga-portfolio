What counts as a closed cycle

A symptom is not a failure and a correction is not a fix. The cycle closes when the correction has been re-measured and the number is in the record. Cycle 1 has a rule the design now follows; cycles 2 and 3 are still looking for a cause; cycle 4 has not been measured at all.

The four cycles below are kept in the order they were found, including the one that is still open, because an open cycle is the most useful thing on the page.

Cycle 1 · Clipping when the gain is too high Fix adopted

The failure that made the project variable-gain in the first place.

SymptomOutput flattens in simulation when a high gain code is used with a larger input, seen side by side with the unclipped case at a lower gain.
Test performedLTspice run of the complete analog model at the same input with two gain settings; input and output compared against the 1 V limit at the XADC node and the 3 V window at the driver.
Root causeInput amplitude × programmed gain exceeded the linear output range. A fixed relationship, not a component fault.
CorrectionGain falls as input rises: the FPGA steps the code down before the output clips. That rule is the whole reason the amplifier is variable-gain.
Re-measured[ PENDING — raise the input at each code until the clipping criterion from WS7 · B.1 is met, and record the largest input that survives ]
LearningA calculated gain is not a usable gain. The setting that works depends on the input amplitude and the destination range, not on the amplifier alone.

Cycle 2 · Every simulated gain reads low Open

All four codes lose gain, and the loss does not scale with the gain.

SymptomLTspice gives 1.9 / 3.1 / 5.6 / 10.8 against theoretical 2.0 / 3.2 / 5.7 / 11.0 — every code low, by −1.8 % to −5.0 %.
Test performedGain read from the simulated input and output waveforms at each code, then compared with 1 + RF/Rin.
What the numbers sayThe shortfall is close to a constant 0.1–0.2 in gain, so the percentage shrinks as gain rises. That is an additive term, not a proportional one — a divider or a reading error, not the feedback ratio drifting.
Root cause[ PENDING — candidates ruled out one at a time: CD4052 on-resistance in the feedback path, op-amp finite open-loop gain at the test frequency, resistor values in the model, probe loading at the measurement node ]
Correction[ PENDING — depends on which candidate survives; a model fix and a design change are both possible ]
Re-measured[ PENDING — bench gain at all four codes (WS6 · C) ]
LearningA systematic error of the same sign at every code points at something shared, not at four separate mistakes.
